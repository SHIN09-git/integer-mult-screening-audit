# 整数乘法成本核验：快速筛选何时省时

**JIN HANZHE · Independent Researcher, Chongqing, China**  
本地发布候选 1.0.0-rc.1 · 研究日期 2026-10-15 · 公开整理 2026-10-22  
[English](README.en.md) · [中文研究说明](docs/中文研究说明.md) · [复现入口](REPRODUCING.md) · [验证记录](VALIDATION.md) · [引用](CITATION.cff)

本项目研究一个具体问题：在整数乘法构造的成本核验中，先做便宜的严格筛选，是否比直接完成精确计算更省时？

结果取决于候选是否能被提前淘汰。对固定的一份旧成本账单，在一个有公开来源的更高目标下，历史计时显示核验总耗时约少 15%；对原本能够通过的目标和筛选无法判断的目标，没有稳定的整体收益。这里的计时对象是成本核验流程，不是完整整数乘法算法。

## 公开价值与核心结果

包内保存同一份输入、两个精确计算实现、提前淘汰与回退规则、故意破坏输入的检查，以及全部 581 个历史进程样本。它适合复用来检查筛选器的收益是否抵得过额外开销。

上游输入为 [PR #2260](https://github.com/CrocSwap/integer-mult-bounds/pull/2260) 的固定成本账单；筛选方法来自 Aaron Wang / navinor 的 [PR #1669](https://github.com/CrocSwap/integer-mult-bounds/pull/1669)。较高目标取自 [PR #2284](https://github.com/CrocSwap/integer-mult-bounds/pull/2284)，始终代入旧账单，没有代入或否定 #2284 改进后的新方案。

| 较高目标下的方法 | 算术部分中位耗时 | 总耗时中位数 | 配对节省中位数 |
| --- | ---: | ---: | ---: |
| 两套完整精确计算 | 61.21 ms | 339.42 ms | 基线 |
| 原二次筛选 | 12.32 ms | 288.20 ms | 15.09% |
| 直接门槛筛选 | 9.19 ms | 286.78 ms | 14.97% |

以上是 2026-10-15、Windows / CPython 3.12.10 的 21 组相邻独立进程比较。百分比先逐组计算，再取中位数，不是两列中位耗时相除。总耗时计入进程启动、来源校验、读取解压、31,392 条辅助位置安排重算、导入及算术；未清空操作系统文件缓存。

在原目标下，安全回退仍执行两套精确计算，历史配对中位耗时增加约 8.92 ms；接近分界点时增加约 6.51 ms。不能用一个容易淘汰的目标推断整场搜索会节省多少时间。

2026-10-22 在 Windows / CPython 3.12.14 上另跑了 581 个新进程样本。同一较高目标下，直接门槛筛选的配对节省中位数为 16.10%；原目标与分界附近仍增加开销。新旧样本分别保存，完整比较见 [中文研究说明](docs/中文研究说明.md)，本次证据见 [验证记录](VALIDATION.md)。

## 一条命令复现

只需 Python 3.12 标准库，无需安装第三方库、Git、网络或 GPU。在解压后的项目根目录执行：

```text
python reproduce.py
```

默认入口会核验文件、重算历史与本次随包计时摘要、重新计算精确结果，并运行语义与篡改检查。它不会重新计时或覆盖随包证据。

| 入口 | 范围 |
| --- | --- |
| `python reproduce.py --mode audit` | 文件一致性、来源与两套随包计时摘要核查 |
| `python reproduce.py` | 再加 10 个“门槛 × 费用模型”组合、17 项语义控制、12 项继承控制、4 项篡改检查及完整原算术结果比对 |
| `python reproduce.py --mode benchmark` | 完成默认核验，再产生 581 个新的进程计时样本 |

每次写入新的 `reproductions/` 子目录。新计时应单独解释；旧机器的 15% 不是验证通过条件。详细命令及输出见 [REPRODUCING.md](REPRODUCING.md)。

## 结果边界

本项目只重算一份完整的已报告成本账单及几个固定门槛。较高门槛是在首轮计时之后发现并加入的补测，不是预注册测试集。四目标混合批次是人为构造，不能当作真实候选分布。

“接受”只说明这个成本函数严格小于 1；“拒绝”只说明它在该目标下严格大于 1。两者都不等同于完整构造可实现或不可实现。本包不刷新复杂度上界，不重做任意规模推广、精度、底层线路及空间安排的全部证明。
